## 错误处理和回归

`acceptance-outage-results.json` 记录了原生消息钩子面对真实本机拒绝连接的结果：普通消息继续进入 Agent，显式记忆命令准确报告失败。此项没有让用户在 QQ 服务离线时再发一次消息。另有真实模型代理请求成功，确认对话模型链路仍可用。

真实命令处理器已使用隔离身份，连真实 SDK 完成“记住 → 查记忆 → 忘记 → 再查不含已删 ID”，见 `acceptance-command-results.json`。这项没有要求用户删除自己的偏好。

排错中出现过一次独立模型探针 503，重启后的同一探针复测通过；模型短暂不可用仍属于需要降级/重试的外部依赖故障。另一次重启后首次召回超过 5 秒，已加入 SDK/向量模型启动预热和最长 30 秒的启动等待，并补充回归测试。

自动化回归覆盖：

- Node：身份跨 `/new` 稳定、不同用户/群隔离、非 QQ Agent 不接入、显式命令、离线降级、消息去重 ID。
- Python：真实 SDK 返回结构的适配、写入失败不伪报成功、删除归属校验、检索来源、HTTP 接口、SQLite 队列重启/去重和删除屏障。

其中 HTTP 合约测试使用 SDK stub；上节独立的七项真实 SDK 验收不使用 stub。安装脚本、最终回归和部署状态另见 `verification-results.json`。

- SDK 提炼/冲突处理依赖模型；不是每条消息都会产生独立记忆。
- 删除可召回事实不会抹除 QQ 历史、DSH 会话或 SDK 原始资料。
- 服务离线时未入队的轮次不会自动补写；已入队任务具备重试和重启恢复。
