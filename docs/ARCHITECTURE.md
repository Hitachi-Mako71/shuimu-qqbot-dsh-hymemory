# 架构

主链路：QQ → 腾讯 DSH QQ 插件 → Hy Memory 身份钩子 → DSH Agent → DeepSeek。模型路由只返回 DeepSeek；图片生成是单独的按需功能，通过本机 Codex 队列提交到 Codex 内置 image_gen。

## 对话和记忆

1. QQ 插件接收私聊、群聊和附件，补充稳定的 QQ 身份。
2. Hy Memory 按 Bot、会话类型和会话 ID 检索长期记忆，并注入本轮上下文。
3. DSH Agent 使用 DeepSeek 回复。
4. 回合结束后只把当前用户消息提交给本机记忆队列；助手生成内容不会自动成为事实。
5. 群与私聊使用不同命名空间；删除记忆会校验当前身份。

记忆服务监听 `127.0.0.1:8765`，模型代理监听 `127.0.0.1:8766`。除健康检查外，本机接口要求 bearer token。Hindsight与本地embedding仅在召回或提炼时启动；请求、原文提炼写入队列及隐私删除操作均空闲后，5分钟释放服务和embedding。首次请求最多等待25秒启动，聊天侧召回最多等待30秒。

## 图片生成

QQ 明确的画图请求形成独立任务，任务文件保存在生图目录，由 Codex 桌面版读取并调用内置图片工具。交付助手校验图片和任务 nonce，机器人收到就绪回执后把图片和原正文发送回原会话。该链路不轮询 Codex 聊天记录，也不转发普通聊天消息。

图片配置、任务状态与角色参考素材位于本机 `data/codex-images` 和 `data/character`，不会进入 Git。

## V1.2 原文层

访问许可 → 原消息/inbox/范围任务同事务保存 → 缓存/清洗/Agent → 草稿与SDK发送准备记录 → 平台回执。Node 和 Python 通过独立证据 SQLite 交换提炼任务，Python 带租约读取原文再调用 Hy；不依赖 HTTP 提交原文，不改写 Hy 旧库。详见 [V1.2](V1_2_EVIDENCE_JOURNAL.md)。
