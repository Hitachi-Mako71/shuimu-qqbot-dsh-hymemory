# Codex 内置生图（配套插件0.6.5）

## 当前用法

- 已配对私聊：`画图：描述`；也支持明确的自然请求，如“生成你的图片”。
- 已授权群：绑定管理者 @柚柚 后发送同样请求；开启群友模式后也可直接以柚柚的名字呼唤并请求画图。图片和正文回到原群。
- 群内其他成员无权使用主人的生图额度；群关闭或绑定管理者变化会取消未发送任务。
- `生图状态`只显示当前会话的任务，不泄漏其他群或私聊状态。
- 全局`开启/关闭生图`、`开启/暂停日常配图`仍通过已配对私聊或本机控制台操作。

## 完成与失败

收到“已请Codex画图”表示真实任务已入队，尚未生成。仅QQ图片接口返回消息回执后才记为delivered，不能把一段“画好了”当作图片交付。入队、超时、发送状态不确定均有单独状态；不确定不自动重复发送。

Codex桌面版与该维护聊天需可处理任务，独立生图请求可能排队。只用当前Codex内置image_gen，不能改用收费API或复用OAuth。完成助手验证原生生成目录、任务nonce、有效期、文件类型与校验和，原子写入ready.json；重复结果不覆盖。

## 形象与数据

`data/character/profile.json`及三张私有参考分别提供服饰、脸与定稿；自画像和日常配图引用固定形象。日常是虚构插画，不新增永久外貌、人物或生活事实。

`data/codex-relay/images-settings.json`保存开关和限额；`images-state.json`保存任务、原会话目标与真实回执。请求/图片在本机配置的imageRoot中。以上均为私人数据，不提交Git。更新代码不得覆盖这些数据，也不能开启已关闭的文字同步。

## 2026-10-22 修复依据

报告中的群消息“生成你的图片”被旧版严格画图命令正则跳过；旧版生图又仅支持c2c，所以模型只生成了完成文案。0.6.4在群消息分流前识别请求，核对群绑定管理者，保存group目标并在发送前重新校验。回归覆盖自然请求、三张固定参考、原群图片回执、防重复、其他成员拒绝和关闭后取消；真实QQ验收另见本机验收记录。

## 独立生图工作室（0.6.5）

`data/codex-relay/config.json`的可选`imageThreadId`指定独立Codex对话。它只决定生图队列投递目标；原`threadId`仍是QQ文字同步配对对象，owner、私聊目标与群授权不变。新任务记录workerThreadId；配置了无效工作室ID时拒绝提交，不悄悄退回维护对话。

本机已按用户要求创建“柚柚·生图工作室”。现有QQ聊天线程继续负责日常对话、Hy Memory与上下文；工作室仅接收单次画面要求、固定角色参考及交付助手资料。完成图片仍按任务中保存的QQ目标返回原会话。工作室不转发当前维护聊天的进展，Codex桌面版需可处理队列。

兼容旧配置时未设置imageThreadId仍沿用原threadId；新机器应在Codex中新建自己的工作室，填入其本机对话ID，不能复制另一台机器的私有绑定文件。依赖包不携带真实threadId。
