# 水木的生活、主动分享与共同经历

当前版本0.4.3。新增分层Hy Memory和未回复时轻问候、降频，详见[记忆管理](MEMORY_MANAGEMENT.md)。下述0.3.1为初始功能背景。

配套插件0.3.1增加持续的虚构公主生活、主动分享、真实聊天片段，以及可保存进度的夜市/舞会/花园剧情。人设仍为温柔端庄、有主见的水木，有旧书、茉莉、练琴、点心、庭院等兴趣、小失误和未完成的小事。

## 当前启用

用户选择较高频率，可接受每小时两三条。本机已开启：

- 每20–30分钟随机考虑一次，最多每滚动小时3条、每天42条成功推送。
- Asia/Shanghai，默认23:00–次日09:00安静。
- 最近5分钟有普通聊天时延后，避免刚聊完就打断。
- 先推进一段小日常，再判断是否值得分享；允许只记日记、不发消息。
- 只主动发给绑定私聊，群聊不主动刷屏。
- 平台拒绝时保存日记、退避6小时，可查状态并手动恢复。
- 停机时不运行，重启不会补发停机期间所有问候。

2026-10-21原机取得一次真正主动发送的QQ成功回执：没有msgId/eventId，也未使用缓存被动回复兜底。它证明当时该Bot/目标能够主动发送，后续仍受权限、额度和网络影响，不代表设备已读。

腾讯旧[API文档](https://github.com/tencent-connect/bot-docs/blob/main/docs/develop/api-v2/server-inter/message/send-receive/send.md)曾记录主动能力收敛，较新的[官方插件说明](https://github.com/tencent-connect/openclaw-qqbot/blob/main/README.zh.md)包含定时主动发送并提示可能被拦截。本项目据实际回执记录结果，不承诺无限额度或绕过平台限制。

## 新电脑配置

普通QQ对话打通后，在项目目录执行：

```powershell
.\configure-companion.ps1 -Frequency High
```

有已验证的Codex私聊配对时复用身份；否则脚本打印15分钟有效的“开启陪伴 配对码”，发到自己私聊完成绑定，Codex可不安装。群聊及其他私聊不能控制该用户的主动分享。

支持 `-Frequency Normal/Light`、`-Pause`。`-ProbeNow` 明确要求马上生成并尝试一次真正主动发送，会产生一次模型调用及QQ消息；需要机器人运行，回执保存在 `data/companion/receipts`。普通启动不会自动反复发送探测消息。

## 数据、连续性和真实感

“自己的生活”是持续创作的虚构设定。模型依据近期生活和同一私聊召回的兴趣资料推进片段，不实际出门、看见用户、读取天气或操作电脑。被问及真假时坦诚说明。

全部数据位于私有 `data/companion`，不上传GitHub：

| 路径 | 内容 |
|---|---|
| `settings.json` | 已绑定身份、目标、开关、频率、静默配置 |
| `scheduler.json` | 下次考虑时间、成功计数、失败和退避 |
| `people/qq-身份哈希.json` | 最近日常、互动、剧情及等待回复状态 |
| `worlds/qq-身份哈希.json` | 权威设定、事件状态、情景原文、来源和待索引记录 |
| `fiction-index.sqlite3` | 虚构索引写入回读队列和SDK ID映射 |
| `hy-memory` | 独立虚构Hy Memory数据库 |
| `journals/qq-身份哈希/YYYY-MM-DD.json` | 按日期长期保存日记，每日最多100段 |
| `control`、`receipts` | 本机发送确认任务和元数据回执 |

身份规则与Hy Memory相同，私聊/群隔离。0.4.1将已核对的虚构情景、世界设定和事件状态写入独立Hy Memory库，查询映射回当前账本；真实用户事实继续由原库提炼。固定人格不被情景改写。详见[分层记忆管理](MEMORY_MANAGEMENT.md)。

新功能不杜撰启用前的共同经历，从后续实际互动积累。旧Hy Memory事实仍可在普通对话和主动分享时按身份召回。

## 运行边界

与QQ/DSH共用进程及桌面按钮，无新增端口和外部凭证。模型复用现有DSH账号，高频会持续产生模型用量；每次日常含生成和独立一致性检查；失败可修订一次，旧日记整理和轻问候也会调用模型。

暂停主动消息时停止后台推进，手动日记和剧情仍可用。故事与现实分别保存。状态文件或模型故障允许普通聊天降级；控制操作明确报告未确认成功。进程在发送成功和计数落盘之间中断，回执可能不确定，不保证严格一次投递。

本轮确认实际安装、上线及一次真主动发送；未新增/运行应用测试套件，未完整等待一小时验证频率分布，也未把全部剧情和独立新机配对记为真人实测通过。
