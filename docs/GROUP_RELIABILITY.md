# 群里叫柚柚却没回应：0.5.4修复

## 实际故障

原机记录表明群友模式为enabled=true，但一次回复出现SyntaxError，程序进入五分钟静默。只读使用同一模型、群上下文和token预算复现时，返回52字符普通文字，不是JSON；旧程序在第0字符就解析失败。故障来自“要求JSON，但模型按日常人格返回文字”的接口契约不一致。

旧实现还有两个丢消息点：群里只保存一个待回应事件，新成员的呼唤会覆盖前一条；冷却中事件被直接取走丢弃。因此即使是不同成员打招呼，也可能没人再处理那句话。

截图中模型将“独立AT事件计数0”归因为QQ权限没开，是无依据推断。全量模式下@也可以作为GROUP_MESSAGE_CREATE送达，不能由这个数字单独判断。

## 修复

- 群回复以最终聊天文字为主，不回复时用固定NO_REPLY标记；兼容旧的有效JSON，但格式不合规不再触发五分钟全群静默。
- 不同成员的直接呼唤分开排队，同一成员尚未处理的重复呼唤合并为最新一条。冷却中的呼唤延迟处理，不立即丢弃；队列最多20项，最长保留120秒。
- 直接呼唤有每成员5秒和群发送最短1秒间隔，普通插话保留原档位冷却。直接呼唤单独限制每群每小时60次，不占普通随机插话的4/12/24条配额。
- 明确呼唤却得到静默或坏格式时，用简短应声兜底。仍遵守群关闭、用户暂停、机器人回声过滤及其他成员被@的规则。
- 群友模式状态等控制命令在进入模型前处理，即便没有识别到@也可查询。支持“群友模式 绑定码”“群友模式绑定码 绑定码”等兼容写法；格式不对直接给用法，不交给工具Agent扫描文件猜测。
- 从SDK的READY身份学习机器人ID，补充全量事件中的自身@识别。状态分别显示独立@事件与实际识别到@的次数。
- 用户“安静十分钟”和系统错误退避分开。模型/网络错误短暂退避15秒，发送结果不确定时不自动重发；启动时解除已确认由旧SyntaxError造成的静默。
- 普通问候自然回应，不继承旧消息中重复道歉、假称忙不过来、没有听见或技术归因的说法。

## 验收与数据

本机已重新安装0.5.4，实际14个插件文件哈希与源码相符、QQ已上线，旧格式错误的暂停时间已归零。用户确认两位成员均已发送问候并查询状态；本机记录两位不同成员的senderReplies与两条kind=called的QQ接受回执，总接话计数由3增至5。全量模式自身@也已识别。最新单次接话8846ms（排队806、检索934、模型3091、发送4015），不代表稳定速度。详见根目录group-reliability-verification.json。未跨第二群或持续一小时验证全部限额，回执也不代表设备已读。

成员回复时间保存在私有groups/rooms中的senderReplies（按群派生成员别名），诊断状态仅保存判断原因、时间、排队数及耗时。它们不提交Git。未新增/运行应用测试套件。
