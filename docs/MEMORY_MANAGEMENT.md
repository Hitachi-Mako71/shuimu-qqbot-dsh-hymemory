# 分层记忆与等待回应（本地 0.4.3）

本版本已在原机部署，源码与部署说明按用户授权归档至 GitHub 私有仓库。人格、真实记忆与虚构生活有不同的管理权限和数据来源。

## 分类和优先级

| 类别 | 保存位置 | 允许怎样改变 |
|---|---|---|
| 底层人格 | `personality.md`；`fiction-canon.json` 的 protected/world_rules | 本机明确编辑；剧情和记忆检索不能改写 |
| 已确认的虚构设定 | 每身份 worlds 账本 facts；Hy Memory world-fact 索引 | 新名字有原文证据才可登记；已存在值只能由明确更正命令改版 |
| 虚构情景记忆 | 原始日记、worlds.events；Hy Memory episodic 索引 | 按发生时间追加，附摘要、来源、检查结果；不重写旧原文 |
| 进行中事件 | worlds.threads；Hy Memory event-state 索引 | 同一事件沿用 ID，保存状态和版本；结束/取消的事件不自动重开 |
| 真实用户事实与偏好 | 原来的用户 Hy Memory 空间、原始聊天与提炼队列 | 沿用记住、查记忆、忘记，SDK 继续负责提炼与冲突处理 |
| 等待回应与重逢状态 | people 中 lastInboundAt、deliveries、attention | 随新消息和时间变化；不提炼成“用户冷淡”等长期性格 |

底层人格优先于剧情；当前确认设定和事件状态优先于旧情景。私聊和群聊按各自身份哈希隔离，只有绑定私聊接收主动消息。所有虚构内容标记 fiction，不声称在现实发生。

## 自动保存和召回

1. 新故事生成前自动召回相关情景，同时提供固定人格、全部已确认设定和事件账本。
2. 候选故事必须提出结构化的 facts/threads，逐字 evidence 必须出现在叙事里。程序检查稳定 ID、名字不可覆盖、状态迁移、容量等约束。
3. 独立模型再次核对叙事、摘要与账本。失败时修订一次；仍失败就不保存为已确认情景、不发送。
4. 先将账本原子落盘，再发布、排入独立 Hy Memory 写入队列。每条索引经 SDK get 回读确认后才标记 done。
5. 召回的 SDK ID 必须映射回当前有效的账本记录；过期设定版本、已隔离日记和清空前的 epoch 不进入上下文。没有 Hy 命中或服务不可用时，明确标记使用本地词组检索。

虚构专用 SDK 运行在独立子进程，使用 `data/companion/hy-memory`，不新增监听端口。它只写入已经提炼核对的条目，单独关闭 `RECONCILE_ENABLED` 和搜索自动去重，防止原始情景与设定互相合并；真实用户 SDK 的默认提炼、合并与冲突处理保持启用。两边使用不同数据库、collection、agent 和派生 user_id。

旧日记逐段核对后迁移。有冲突或未能确认的片段保留原文并隔离，不作为权威事实，也不进入虚构向量索引。现有一段旧日记处于待核对状态；可以查看，不自动采信。模型检查降低矛盾概率，不能保证所有语义矛盾都可识别。

## QQ 控制

| 消息 | 作用 |
|---|---|
| `生活设定` | 分开查看固定人格、确认设定、F 编号及来源 |
| `事件进度` | 查看进行中和最近结束的事情 |
| `生活记忆状态` | 本地数量、迁移/隔离数、Hy 写入回读及待处理数 |
| `查生活记忆 花园` | 召回相关虚构记录，显示来源 ID 和 Hy ID，或说明本地降级 |
| `待核对日记` | 查看隔离记录和核对原因 |
| `更正生活设定 F编号：新值` | 明确更正已有设定，保留旧值来源与版本历史 |
| `写一段日常` | 手动生成并核对一段新日常 |
| `清空陪伴记录` | 删除本机日记、故事与互动记录，立即换 epoch 隔离旧虚构索引，后台删除旧 Hy 空间；真实用户记忆另行保留 |

清空不撤回 QQ 已发送消息，不抹除 DSH 会话和离线备份。个人事实仍用原来的 `查记忆`、`忘记：ID` 管理。

## 没有回应时的节奏

高频 20–30 分钟只适用于可以自然分享的时候，不承诺机械发送。

- 发送一条生活分享后，没有新消息就先等待，最早 45 分钟后轻轻问候一次。
- 仍没回应，下一次至少相隔 4 小时；继续沉默则最多每天一次轻问候。仍受夜间静默、暂停、忙碌和平台限额约束。
- 等待过程中可以隔约 90 分钟续写私人日记，不向用户连续堆送。
- 用户回来即结束本轮等待；普通回复提供重逢上下文，先接当前话题，不补发积压日记。
- “我先忙”“晚点回你”“先别打扰我”暂缓两小时；“晚安”“我睡了”等暂缓八小时。已有暂停与安静两小时命令继续生效。

角色可以轻轻想念、有短暂落寞和礼貌问候；不假称已读，不猜测去向或拒绝，不责备、查岗、用依赖感索取回复。轻问候另有独立内容检查；检查失败不发送。沉默不写成用户性格或关系恶化的长期事实。

## 数据和恢复

关闭机器人后备份整个私有 `data/companion`：worlds、journals、people、fiction-index.sqlite3 及 companion/hy-memory 都需要。SQLite 运行中有 WAL 文件，不能只复制单个 .sqlite3。原来的真实记忆 JSON 导出不包含虚构库；虚构账本和日记本身是 JSON，但完整恢复还需要对应索引与版本信息。

personality.md 与 fiction-canon.json 属于部署配置；修改固定人格需同步编辑两者，并重新应用 personality_config.py、重启机器人。不要把凭证、个人世界账本或真实聊天上传到源码仓库。

## 本次实际范围
