# 回复速度（0.5.1，本地）

## 排查结果

原机独立测量中，真实记忆检索约83ms、虚构检索约84ms，短文本模型请求约1058ms。此前一条未@群接话从最后一条人类消息到发送约13.25秒。以上是少量实测样本，不是稳定延迟承诺。

源码与正式会话元数据确认：群友模式使用可无限重置的6秒等待；普通群接话有90秒冷却；正式QQ会话还在生成思考块。虽然旧profile的默认模型写了off，显式模型路由和恢复的会话仍会继承其他设置。私聊也关闭了原生流式输出。

## 本次修改

- 群接话改为固定800ms收集窗口，新消息不会把计时无限往后推。
- 最近上下文压缩到12条，省去模型不需要的QQ消息ID、毫秒时间戳等字段；短记忆和回复长度受限。模型仍可选择不发言。
- 未@但明确叫“水木/公主”的接话，最短间隔改为5秒，判断间隔3秒；普通插话的冷却和各档每小时上限保留。
- 判断期间有少量新消息时，允许在10秒内接上原话题；超过窗口、别人被@、用户暂停/关闭或正式@对话时仍放弃旧候选。
- 只对QQ Agent安装作用域内的agent/request扩展，在继承配置解析后明确设置reasoningEffort=off，覆盖已恢复会话。其他profile和Codex不受影响。
- 私聊打开腾讯原生流式输出，有正文就逐步显示。SDK保留失败后的静态发送兜底；QQ群平台不支持这条流式接口，仍整段发送。
- 普通聊天不为了确认称呼、情绪或功能说明去扫描项目文件；明确任务继续使用原有工具链路。

没有关闭自动记忆召回，也没有删除会话或重置人格。每群lastTimings只记录排队、召回、模型、发送耗时，不记录额外聊天正文。每次模型网络耗时会波动，工具任务和复杂问题可能仍较慢。

## 配置与回退

新部署的dsh-qqbot.patch.yml已开启streaming。升级原机时运行：

```powershell
.\.venv\Scripts\python.exe .\configure-response-speed.py --profile D:\DeepSeekHarnessData\home\profiles\qqbot
```

该工具只改独立qqbot profile的streaming并备份原配置，不改会话。关闭流式可追加 `--no-streaming`，修改后重启机器人。

QQ请求默认关闭思考。复杂任务需要更多推理时，可在本机.env设置 `QQBOT_REASONING_EFFORT=high` 后重启（可用值由所选provider支持情况决定）。这是QQ范围的配置，不会改变全局桌面/web profile。

## 观察范围

安装后应检查实际node_modules源码哈希、Bot ready、真实QQ请求是否不再生成思考块、私聊显示体验，以及群接话lastTimings。原机测量摘要在response-speed-verification.json，后续效果以真实消息记录为准。未新增或运行应用测试套件，不把固定等待缩短直接当成所有场景都已达到某个速度。
