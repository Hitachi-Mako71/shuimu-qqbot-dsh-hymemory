# V1.1.0 路由与身份边界

产品里程碑 V1.1.0，Hy Memory 插件 0.10.0，身份请求契约 1；沿用现有 Hy Memory 数据结构及原分区哈希。源码工作树、安装状态、本地验证与 QQ 真人验收分别记录，未创建正式发布标签。

已部署到本机专用 QQ profile。21 项合成检查通过；安装后的 20 个插件文件与源码逐字节相同，官方 QQ 的 6 个改动文件与生成结果在 LF/CRLF 归一后相同。QQ 上线日志、SDK、嵌入模型和提炼代理均已确认就绪。主模型、凭证、人设、群绑定及生图配置保持原值。结果记录在仓库根目录 `v1.1-verification.json`；实际 QQ 平台验收仍待正常使用核对。

## 行为

- QQ 主聊天从本机模型路由取值，提炼代理从独立 `MEMORY_DSH_MODEL` 取值，提供方均固定为 DeepSeek。先判断原始 `mode`，显式工作模式跳过记忆检索、记忆命令、入队及陪伴状态写入。
- 网关提供应用 owner、会话 space 和发言 actor。服务端核对本机 AppID、私聊 actor 与 peer、群绑定，并自行计算原有 `qq-<hash>` 分区。不同私聊、群聊和应用不共用分区；/new 不改变身份。
- 接口不接受任意 bank、批量 user_ids 或其他 agent_id。即使 SDK 意外返回明确属于另一分区的数据，也会丢弃。群成员资料带稳定的群内作者标记；旧无作者标记的摘要不保证自动补出作者。
- 每个私聊或群使用 `data/workspaces/<namespace>`。本轮及引用附件复制到该目录，路径检查同时核对真实路径与目录联接；文件只能发送回当前会话。
- QQ 工具权限限定为文件、视觉、联网搜索及当前会话交互。命令行、进程、插件设置、跨会话工具不对 QQ Agent 开放；文件权限不能通过升级请求扩大。
- 群友模式绑定并开启后才允许持久记忆和旁听缓存。未绑定群只处理主动 @机器人的本轮资料；群记忆删除需要绑定人的 actor。轻问候、群友插话及 Codex 图片在发送前再次检查许可和当前目标。

## 迁移与回退

不更改记忆分区编号，不搬动 Hy 数据库，不重新安装 Python 或 DSH。旧共享文件目录不自动复制到任一身份；保留原件，由本机管理员按真实归属单独处理。旧图片元数据缓存不带新采集标记时不再用于引用；原文件不删除。

旧队列中无法验证身份或授权的待处理任务保存为 `blocked`，证据 payload 保留供本机复核，不自动重放。已有完成记忆不因本次升级清除。之后关闭群采集会阻止尚未执行的该群提炼继续写回。

部署前在本机 `.run/releases` 备份本次涉及的源文件、插件包、专用 profile manifest、依赖锁和 QQ 补丁。可停用新增工作工具或暂停记忆来维持普通聊天；不能通过回退重新开放跨身份目录或任意记忆分区。原有凭证、登录、人格、主模型选择、群绑定与生图绑定按原配置保留。

## 核对范围

本版使用临时合成身份核对：私聊与群分区、/new 稳定身份、工作模式零记忆请求、伪造 owner/actor/bank 拒绝、未绑定群拒绝、跨分区返回值丢弃、路径越界与目录联接拒绝、附件隔离、跨目标发送拒绝和暂停后自动发送拒绝。QQ 官方补丁另核对可应用、重复转换不改变字节和 JS 语法。

上述本地检查不代表 QQ 平台已接受真实文本、图片或文件。部署启动就绪后，仍需在正常使用中核对私聊和授权群的实际收发，以及一个完整活跃周期；V1.0 的既有完整平台回归缺口不因本版自动变为通过。

## 调试记录

- 补丁构建首次读取被 Windows 默认 GBK 编码阻断；改为显式 UTF-8 后，重新生成、重复转换与语法检查通过。
- 本地检查首次遇到沙盒禁止目录联接、loopback socket 和部分临时目录清理。确认异常为 EPERM / WinError 10013；检查请求改为显式无代理和有限超时，临时服务数据固定在工作区。随后在获准环境中，目录联接和模拟 HTTP 契约检查通过；没有为通过检查放宽生产权限。
- 首次部署出现 `ERR_PNPM_PATCH_FAILED`。追溯发现构建脚本在 Git 子目录调用 apply，Git 忽略不属于该子目录的路径，错误生成了相对旧补丁的增量；此前的 check 因同一原因漏检。第一次改为官方原件与 no-index 后，真实文件对比仍发现未应用；第二次隔离 Git 仓库发现后，实际应用成功，但严格字节检查遇到 LF/CRLF 差异。两次验证未通过后，按 `superpowers:systematic-debugging` 重新核对六个文件：差异仅是换行。最终检查限定只归一 LF/CRLF，实际应用完整补丁、逐文件比对内容，并保留安装后的真实字节哈希核对。失败部署和原版文件备份保留在本机受限 release 目录。
- 完整补丁重新部署后，检查脚本曾因 `ReadAllText` 与运行日志的共享锁冲突而误报未就绪。分别查询三个健康标志及启动日志确认服务已上线，随后将该脚本改为现有控制台同样的 ReadWrite/Delete 共享读取方式；没有再次重启或更改生产服务来消除误报。
