# V1.2 双方原话与可重放提炼任务

产品里程碑 1.2.0，本地插件 0.11.0，证据库 schema 1。仍使用 DeepSeek 对话和 Hy Memory 提炼，Codex 仅承担独立手动生图。没有恢复阅读、虚构生活或其他文字模型桥接。

## 数据先保存，再处理

在 QQ 访问许可校验之后、历史缓存与内容清洗之前，保存网关提供的完整消息对象、文本、原始时间、空间、发言者及消息 ID。原文、inbox 和提炼任务引用在一个 SQLite 事务中提交，随后才进入 Agent。新库位于 `data/evidence/qq-evidence.sqlite3`，与旧 Hy 数据库、身份工作目录分开。启动器先限制目录权限，再启动服务。

相同空间与平台消息 ID 只归档和分派一次。提交失败时不运行 Agent，避免出现处理过但没有原文证据的回合。记忆服务或模型暂时不可用不影响 Node 保存原文。平台在机器人离线期间未投递的消息无法补取；没有真实原话的旧摘要不导入此库。

`evidence_events` 保留有序序号、稳定 ID、user/assistant 角色、发言者、来源时间和记录时间。`raw_json` 保存 SDK 的原始消息对象（含 SDK 提供的网关原事件），不保存 Bot 实例、请求鉴权头或账户配置。附件记录元数据和路径，不承诺永久保存原附件字节。

## 助手说了什么，与实际发送分开

- `draft`：完整模型草稿或流式快照，没有平台送达证明。
- `prepared`：SDK 调用前已保存准备发送的正文与目标。
- `accepted`：取得平台消息 ID，记录实际发送正文及回执；只表示平台接受，不表示用户已读。
- `rejected`：平台明确拒绝的调用。
- `unknown`：网络异常、缺少最终回执，或准备发送后进程中断；不能当作发送成功。

分块发送的每个实际块分别记录。SDK 内部嵌套发送不产生两份相同尝试。合并入站仍保留全部源消息，群聊不丢发言者。轻问候、控制命令、图片说明和失败提示可留收发记录，但不作为新的真实用户事实自动提炼。

## 提炼与恢复

`evidence_jobs` 只引用不可变原文和 Unicode 字符范围，不复制并截短唯一原文。每窗最多 6000 个 Unicode 码点；助手任务可附带同轮最多 6000 个码点的用户背景。每段用户原文都有自己的任务，因此背景窗口的限制不会丢掉唯一原文。

只有用户实际输入和有真实回执的助手正文进入提炼。两侧角色保持独立，源 ID、范围、时间及发送状态透传到 Hy `meta.evidence`。提炼说明要求将助手原话视为对话证据，不能当成用户同意、用户事实、工具完成或现实经历。

任务 ID 由原文 ID 和范围稳定派生；SQLite 事务领取、带令牌的租约、续租及确认防止正常并发与重复投递重复取任务。崩溃后超时租约可再次领取同一个请求 ID，成功任务不重复入队。Hy 是独立存储事务：若 SDK 已写入而本地确认前崩溃，重放会复用请求 ID 和证据引用，但不把此机制宣称为第三方 SDK 所有副作用的严格 exactly-once 保证。

重放的是提炼任务。未完成 inbox 和不确定发送保留证据供核对，**不自动重跑 Agent、工具或向 QQ 重发**，以免重复操作。`handled` 表示中间件已消费消息，不代表平台已接受回复；平台结果以独立发送回执为准。

## 开关、删除和边界

- `QQBOT_EVIDENCE_EXTRACT_ENABLED=false`：暂停后台提炼，继续保存新原文和任务。
- `QQBOT_EVIDENCE_ENABLED=false`：停止新原文采集；已有原文保留。若还需停止旧任务处理，同时关闭上一个开关。
- 工作模式和未绑定群不会建立此长期原文存档。每个群与私聊仍使用 V1.1 的身份分区；群采集须已绑定开启。
- 原有“忘记：ID”删除该条提炼记忆，并取消此前任务、设置语义截止位置，防止旧消息的延迟回复重新入队。此版不物理清除聊天原文；完整原文删除、恢复和备份屏障属于 V1.3。
- 默认持续保留原文，没有自动淘汰；后续生命周期功能处理保留和删除策略。

V1.2 不新增近期原文注入、历史回源工具或新会话自动恢复；分别按 V2.0、V2.1 推进。

## 局部检查与调试记录

使用合成消息和假回执检查完整长文本、事务回滚、入站去重、进程重启、两角色、未知/拒绝状态、并发身份、合并来源、授权群、回执缺失、续租重放、删除截止及暂停提炼。保留 V1.1 的身份/文件边界和旧接口兼容检查。没有向真实 QQ 会话自动发送验收消息。

Python 队列首轮检查发现的是检查程序自身的问题：SQLite 的上下文管理器不会关闭连接，导致 Windows 清理被锁；同时重试检查误把公平调度等同于立即优先重试。显式关闭检查连接、等待同一任务重新被领取后，5 项队列检查通过。未更改生产队列的公平调度来迎合错误假设。

部署结果与检查数量记录在 `v1.2-verification.json`。服务健康和文件一致性不等于 QQ 真人收发验收。
