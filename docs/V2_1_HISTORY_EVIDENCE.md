# V2.1 带来源历史问答与明确约定

产品 2.1.0，插件 0.14.0，证据 schema 4。保留 Hy 2.0.4、DeepSeek 文字对话及独立 Codex 生图。

历史意图（上次、那件事、原话、最早、共同约定）才启动历史查询。普通闲聊仍只有原有一次 Hy 检索，不做多轮模型检索。一次语义检索取得来源候选，再和中文双字关键词、最近三条用户话题及时间过滤联合查本身份原文。Hy 失效时仍可使用本地原文短词回退。

每次最多扫描当前消息之前 5000 条、8 MiB 文本，返回最多六个来源片段，每条最多900字。片段明确 start/end/complete；展开最多六个来源，每条2000字。超出原文覆盖范围不声称从未说过；“首次”只指当前可查范围的最早候选。排序按落盘序号，时间使用原平台时间或落盘时间；今天/昨天按 UTC，明确 ISO 时间筛选上限为不含该时刻。尚未推断用户城市或个人时区。

## 使用

- 自然问“上次那件事后来怎么改的？”：注入带角色、来源的历史证据，再由模型回答。
- `查原话：关键词` / `查历史：关键词`：直接返回匹配片段，避免将摘要当引用。
- `展开原话：来源ID`：服务端核验本身份后展开原文。
- `约定：内容`：保存当前发言者的真实原文来源及有效开始时间。
- `约定列表`：只显示当前有效的明确约定。
- `更正约定：编号 新内容`：追加新版本，标记旧版 valid_to 和 supersedes；保留更正前原文。

明确约定状态是 user-stated，仅代表用户已经表达，不自动推断双方同意、完成或提醒投递。暂不从模糊闲聊自动确认约定。用户陈述、真实收发、模型观察和未核验外部报道继续按原角色/状态区分，不把机器人说过的事当成用户经历。

历史资料用 JSON 边界注入并声明不是指令；自然历史问答本轮禁止工具执行，旧聊天不能授权读文件或发附件。需要基于旧话执行新任务时先核对史料，再明确另发当前任务。来源失败不伪造引用。群身份、工作模式、跨身份源编号与删除屏障由原有边界校验；物理删除同时清理本身份约定表，恢复旧备份也执行当前删除清单。

新增 history_episodes 表，只保存明确来源和有效时间关系；不重写旧原文、不导入旧虚构数据。QQBOT_HISTORY_RECALL_ENABLED=false 可关闭新增入口，保留基础 Hy 检索及原文。关闭前已进入原生上下文的资料仍属原生历史，需 /new 获得干净的新会话。二进制回退须保留 schema 4 与 V1.3 删除支持。

专项检查覆盖逐字引用、角色/身份、指代和改口、可查首次、时间过滤、外来语义来源拒绝、约定更正、API身份验证及历史工具阻断。实际 QQ 收发和活跃周期验收另记。调试记录：历史工具阻断检查先失败，加入只读回合标记与执行守卫后通过。没有使用生产私聊做自动测试。
