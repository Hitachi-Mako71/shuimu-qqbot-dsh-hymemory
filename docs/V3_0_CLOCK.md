## 用户可以做什么

| QQ 输入 | 行为 |
|---|---|
| `设置时区：Asia/Shanghai` | 明确确认当前私聊时区；绑定群中仅控制人可修改群时区 |
| `时区状态` / `清除时区` | 查询确认记录或撤销当前设置 |
| `现在几点` / `今天星期几` | 按需采样系统时钟，返回本地时间、星期、IANA 时区、offset 和 UTC 采样时刻 |
| `明天星期几` | 由程序按当前已确认时区推算日期和星期 |
| `北京时间` / `UTC时间` | 明确指定本次查询的显示时区，保持会话设置 |
| `时间计算：明天18:00` | 按本地日历解析明天的指定时刻，返回 UTC 与实际 offset |
| `时间计算：下周一` | 返回日期和星期，精度为日期，不补造时刻 |
| `时间计算：两小时后` | 按真实经过秒数计算，跨 DST 时保持持续时间 |
| `倒计时：明天18:00` | 相对于同一次 sampled_at 计算剩余秒数；过期时显示已经过去 |
| `时区换算：2026-11-01 01:30 \| America/New_York \| Asia/Shanghai` | 换算两个明确时区，重复时刻先返回候选 |

复杂问法可由 Agent 调用 `qqbot_clock`。该工具只有读取和计算能力，没有修改设置或创建提醒的操作。输入的相对时间原词交给程序；缺少日期、时区或上午下午时请求补足。


遇到重复时刻，直接命令也可在完整输入末尾加 `| 较早` 或 `| 较晚`，例如 `时区换算：2026-11-01 01:30 | America/New_York | UTC | 较早`；不依赖模型记住上一条直接命令回复。

## 时间契约

- 每次实际调用只执行一次 `Date.now()`，`sampled_at` 以 UTC ISO 格式给出。当前 UTC、本地表示和倒计时都来自同一个采样。
- 标明 IANA `time_zone`、`offset`、`offset_seconds`；日期查询给出 `precision=date`，不将日期自动解释为午夜。
- 本地日历日期与经过秒数分开计算。“明天”按所选时区的日历推进；“两小时后”按持续时间推进。
- 本周从周一开始。支持本/这/上/下周加星期、一至九十九的常用中文数字、数字天/周前后、数字秒/分钟/小时前后、ISO 完整日期和时刻。
- 中文几点需要上午/下午等限定；24 小时 `HH:mm` 可直接输入。仅给月份日期、下个月、节日名称或无法唯一解析的复杂表达式返回澄清要求，不由模型补算。
- 本地时刻先生成候选，再按实际 IANA 规则回转核对。DST 缺失时刻返回 `nonexistent_local_time`；重复时刻返回 `ambiguous_local_time` 与两个候选。只有用户明确选定后，工具才使用 `earlier` / `later`。
- UTC 内部表示不受机器本地时区、VPN 或服务器迁移影响；用户时区从当前 QQ 身份的显式设置读取，不从城市、机器或旧记忆推断。
- 精度依赖操作系统墙上时钟；没有新增 NTP 同步或对系统时间正确性的额外承诺。

## Windows 时区数据来源

采用当前已安装的 Node.js `Intl.DateTimeFormat` / ICU IANA tzdb，无新增 Python 包或数据库。每次查询返回 `source.node`、`source.icu`、`source.tzdb`。本次只读环境观察为 Node 24.11.1、ICU 77.1、tzdb 2025b；这是本机依赖信息，未作为所有部署的恒定值硬编码。

官方依据：

https://nodejs.org/api/intl.html

https://nodejs.org/api/process.html#processversions

不启用 DSH 自带的持久 time-context 组件，也不增加每轮时钟快照、定时刷新、时间缓存或后台 worker。现有聊天原文及真正使用工具时的会话记录仍按原有证据策略保存。

## 身份、设置与删除

`clock.js` 从 QQ 网关身份派生原有 namespace，禁止模型传入任意身份。私聊与各群的设置互相独立。未绑定群可做明确时区的瞬时查询，不持久化群时区。

设置通过当前用户的原始 `设置时区：...` / `清除时区` 命令提交，模型工具没有设置接口。群修改在实际提交前重新核对绑定管理者。现有 `withPerson` 串行锁保持同身份配置的并发更新顺序；提交前重核删除状态与版本。

设置保存在现有受管 `data/companion/people/<namespace>.json` 的 `clock` 字段，包含 schema、时区、revision 和确认时刻；清除保留递增 revision 的空设置。没有新建身份数据库、长期索引或来源副本。

既有 V1.3 `retire_caches` 会在删除维护中移除该身份 companion 文件；旧备份恢复继续受现有删除权威约束。逻辑遗忘也可能清掉此缓存，从而要求重新确认时区，不回退到旧设置。支持范围沿用启动器设置的受管 companion 目录。

时钟控制命令的双方原文保留在独立证据库；这些控制消息不进入长期提炼队列。普通对话、Hindsight 单主链路与工作模式的记忆跳过规则沿用原实现。工具继续经过现有文件/身份 guard，历史只读回合不得借旧指令调用工具。

## 合并、部署与回退

分发包 `Apply-SourcePatch.ps1` 默认只核对源目录。核对每个目标文件的改前/改后 SHA256；已匹配改后的文件跳过，出现其他改动即拒绝覆盖。`-Apply` 只把列出的公共文件合并到源码，先将原字节备份至源码 `.tmp/clock-source-patch/<stamp>`。不复制或替换整个仓库，不 reset/clean，不修改任何生产数据。

在有写权限的项目会话中完成源合并后，使用本版 tgz 更新专用 qqbot profile。安装前核对当前生产公共文件的差异，备份被替换的代码和 profile 包管理文件，再经现有受管入口停止服务。只安装本地插件包，不运行完整 install-qqbot.ps1，不重装 DSH/Hindsight，不迁移数据库或覆盖用户配置。

通过 DSH 已有 plugin add 更新 `dsh-hymemory-qq-0.16.0.tgz`，检查 package.json、实际安装文件和 profile lock；27 个安装文件应与本版源码逐字一致。用现有 start-all.ps1 启动，再分别记录安装、健康与 QQ 实际验收结果。运行恢复后才能把发布状态改为已部署。

关闭 `QQBOT_CLOCK_ENABLED` 可停用本版功能。需要撤回插件时，恢复部署前插件及 profile 包管理文件，保留全部原文、独立删除账本和 Hindsight 数据；不能回退到不支持当前删除/schema 的旧产品版本。source patch 的改前字节备份仅用于本版源文件合并，不充当生产数据备份。
