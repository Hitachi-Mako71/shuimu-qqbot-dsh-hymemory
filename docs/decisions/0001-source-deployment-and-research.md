# ADR 0001：源码、部署与研究分离

状态：采用。日期：2026-11-01。

## 背景

此前本机运行目录同时承担源码、临时实验和历史验收归档职责，GitHub虽已有app/，本地却没有同构的干净Git工作副本。发布时容易漏文件、混入本机信息，旧报告也容易被误读为当前状态。

## 决定

- 仓库使用app/保存可部署应用；其内部路径作为运行契约保留。
- docs/保存当前教程、操作指南、开发说明和技术参考；研究笔记和显式实验入口集中research/。
- archive/保存旧包与停用组件；.run/只作本机临时证据，不提交。
- 本机源码工作副本与现有部署目录并列；已有运行数据、进程和安装profile不随整理迁移。
- 固定插件包及其源码、官方补丁保持原始字节，避免换行处理破坏包哈希和补丁锁。其他文本文档使用Git换行规则。
- 发布前自动检查目录、活动文档链接、源码与包、依赖锁和禁止提交的路径。

## 影响

本机维护以源码仓库为准，部署需单独发布；新增一次受审查的部署动作，换来清晰的代码/配置/运行边界。没有把“仓库结构通过”当成QQ收发或回复自然度验收。
