# 目录调整与已有部署升级

仓库现在把完整的可运行工程放在 `app/`，文档放在 `docs/`，历史材料放在 `archive/`。Python 模块、PowerShell 启动器和插件在工程内部的相对位置保持一致。

## 新部署

克隆仓库后先进入 `<仓库路径>\app`，再运行安装、配置和启动脚本。例子见 [Windows 基础安装](windows.md)。生成的私有数据也位于这个应用目录下。

## 已运行的部署

现有部署目录不需要因为 GitHub 整理而迁移。本次目录调整没有改变业务插件版本或运行代码；已有 `D:\DeepSeekHarnessData\qqbot-hymemory` 实例可以继续按原入口运行。

之后更新源码时，建议在另一个目录获取新仓库，把 `app/` 视为公开工程的来源。按照[发布流程](../development/releasing.md)备份、比较并更新需要的源码和插件；不要将仓库根目录直接覆盖到现有应用目录，也不要用新模板覆盖 `.env`、私有映射、`data/` 或 `.privacy/`。

如果准备改为直接从 checkout 的 `app/` 运行，需要另外规划数据迁移和启动路径，并按[备份与恢复](backup-and-recovery.md)处理。这不属于一次普通 `git pull`。
