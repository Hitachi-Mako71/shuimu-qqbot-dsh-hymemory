# 私聊问候召回延迟 — 2026-11-03

## 根因

0.22.39 收到“我回来了”至 QQ 发出回复约 20 秒。匿名阶段指标为：Hindsight `/search` 14.2 秒、主模型 3.76 秒、发送 0.246 秒，主轮一次模型调用、零工具调用。启用的会话策略只跳过一个很窄的独立问候白名单，“我回来了”未命中，于是做了对这条简单寒暄无用的长期记忆召回。

## 修复

0.22.40 将独立“回来/回来了/回来啦”等简短寒暄加入相同快速路径。只有整条消息完全匹配时才跳过；“我回来了，之前那个文件继续弄吧”等包含历史依赖的消息仍召回。没有缩短 Hindsight 超时，也没有改变历史查询和其它个性化检索规则。

先加最小回归覆盖后，本地用例重现了原行为：两条新断言失败，历史引用仍按原规则召回。实现修正后，指定 `conversation-policy` 本地用例 11 项通过。它们是代码级回归核验，不是真实 QQ 测试。

## 验收

0.22.40 部署后，用户在同一私聊再次发送“我回来了”，机器人真实回复“你回来啦”。QQ 入站日志 21:50:25、发出日志 21:50:28；阶段指标为入站 21:50:25.368Z、主模型 1.527 秒、发送 0.203 秒、发出 21:50:28.763Z，端到端约 3.4 秒。该轮没有 `recall` 或 `memory_http` 搜索指标，主轮一次模型调用、零工具调用。相对 0.22.39 约 20 秒样本，本次样本快约 83%；这是单句单轮结果，不是整体延迟承诺。详细本机证据位于 `.run/deployment-evidence-0.22.40-20261103.json`。
