# 文件任务延迟与 DeepSeek 连接修复 0.22.33

## 真实问题

0.22.32 的真实 QQ 请求“读取刚才的两份 md 文件，分别概括标题和第一节”收到正确摘要，但从入站到平台接受回复耗时 88.425 秒；Agent 开始前等待 31.270 秒，生成阶段 57.155 秒，出现四次 TRANSPORT 重试。该轮复用了此前实际 read 的文件上下文，没有再次读取；不能将其描述为新附件上传验收。

## 根因与修复尝试

按照 systematic-debugging，先收集时间线和最小复现，再修改业务逻辑。本轮只有一组生产修复，尚无两次已验证失败的生产修复。

1. 路由：historyPlan 将“刚才”作为模糊聊天历史查询信号，误接收当前文件任务；历史接口允许等待 30 秒，成功时还会进入 historyOnly，限制文件工具。先增加用例观察到 5 项失败，再增加保守的当前文件任务识别，绕过模糊历史路由及可选语义召回。显式查历史/查原话、个人偏好及混合历史任务仍走原检索；实际文件操作继续受现有身份工作区权限约束。
2. 连接：同一 DeepSeek 地址，curl 返回 HTTP 401，Node 默认协商却在约 10.7 秒后连接超时；本地代理 TCP 可达，显式代理仍超时。仅限制 TLS 版本为 1.2，或仅将密钥交换组设为 X25519:P-256，均可恢复连接。采用后者，真实探针仍协商 TLS 1.3，374 毫秒收到 HTTP 401。现有证据说明默认组协商与当前网络路径存在兼容问题，尚不足以判定具体是哪一代理或哪一个默认组导致。
3. QQ 专用 Node 进程加载插件时设置兼容组；尊重已有显式曲线配置，可用 QQBOT_TLS_CURVE_MODE=system 保留 Node 默认行为。没有修改 TLS 版本上下限、密码套件、证书校验或全机设置。官方 API 说明见 [Node TLS 文档](https://nodejs.org/download/release/v24.11.1/docs/api/tls.html#tlsdefault_ecdh_curve)。

诊断期间的代理探针是定位实验，不是部署后失败的修复。离线核验入口第一次拒绝含点的标签，之后一次从错误目录调用失败；修正调用目录与标签后执行完成，没有因此更改业务实现。

## 验证边界

- 离线合成核验：39 个文件、443 项通过，失败 0；包括当前附件路由、混合个人历史请求及 TLS 配置保留。
- 真实 DeepSeek 测试：同一运行中模型代理，修复前最小请求 HTTP 503 / TRANSPORT，10.776 秒；部署后连续三次 HTTP 200、正文 OK，耗时 1.447、0.552、0.471 秒。此处不代表完整 QQ 端到端耗时。
- 健康检查：OneBot ready；记忆服务 ok、sdk_ready、embedding_ready 为真，模型代理正常。源码、运行副本、活动 profile 的 81 个插件文件哈希全部相同。
- 0.22.33 真实 QQ 测试：用户重新发送相同请求，已核对接受状态、平台消息回执与入站来源谱系；同口径的入站记录到出站记录耗时由 88.425 秒降至 9.349 秒，缩短 89.4%。Agent 前等待由 31.270 秒降至 1.320 秒，单次模型调用、零 TRANSPORT 重试。回复的两份文档标题及编号第 1 节摘要已与真实文件核对；本轮没有新增工具调用，复用此前实际 read 内容，不是重新上传验收。句尾中文句号处理保留，参与模式保持 off。
- 本机记录保留在私有 .run，源码仓库与插件包不含实际聊天、附件、账号映射或凭证。

## 部署与回退

发布版本 0.22.33；更新版本包、固定版本及两套 profile 锁文件，通过受管理脚本重启。部署前保存了 0.22.32 插件、版本、包和 profile 清单/锁文件。回退时使用这些备份恢复并通过原脚本重新启动，不覆盖私人 data/、.env 或身份映射。
