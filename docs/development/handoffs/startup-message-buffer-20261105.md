# OneBot 启动消息暂存 0.22.45 — 2026-11-05

## 真实现象与定位

用户在 21:31 的更新重连附近发出后续阅读消息，QQ 截图及 NapCat 在 21:31:50 的接收记录可见，但原生会话没有对应新模型轮次，证据库也没有该条入站。21:35:56 新的明确 @ 请求正常进入并于约 21:35:59 完成回复，服务没有持续卡死。

实际请求头（seq 811）确认 provider=deepseek-account、model=deepseek-flash、reasoningEffort=off；maxTokens 大小不是思考档位。源码 configureQQResponseSpeed 固定使用本机配置的档位，当前没有按“仔细看看”自动升档。本次没有更改它。

接入代码仅在 online=true 时交付，握手前直接忽略消息；online 在 onReady 完成前已设真，又可能把消息交给未完成初始化的机器人。真实消息的精确到达顺序未记录握手相对时刻，不能断言已穷尽所有漏交原因；合成握手时序已确定性复现这两个窗口。

## 修复

同一 socket 代次收到的已声明为当前账号的消息/文件通知，握手或 onReady 未完成时先短暂暂存；账号核验与 onReady 完成后按到达顺序启动原入站流程。后续仍走既有归一化、群授权、消息去重及隐私边界。

队列最多 32 条、总计 1 MiB、每条最长 30 秒；溢出/过期只记匿名状态，不记录正文。停止、断线或旧连接代次失效时丢弃缓存；错误账号不放行。没有磁盘原文新库，也没有离线补拉或未知发送/工具重放。
