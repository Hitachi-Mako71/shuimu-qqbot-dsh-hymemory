# V2.3 Hindsight 记忆接入

用户明确要求实际安装 Hindsight。此前仅做预检、保留 Hy 的方案已由本次要求取代；不宣称已证明 Hindsight 比 Hy 质量更高。

## 安装与运行

- 独立 `hindsight/.venv`：Hindsight API/client 1.1.0、pg0-embedded 0.15.2、FlashRank 0.2.10。完整依赖固定在 requirements-hindsight-lock.txt。
- Windows 原生 PostgreSQL 18.1.0 + pgvector。数据在 `hindsight/postgres`，接口只监听 127.0.0.1:8889，数据库只监听本机 55439。
- 中文向量继续使用本机 BAAI/bge-small-zh-v1.5（512维）；重排使用多语言 ms-marco-MultiBERT-L-12，CPU 运行。
- 提炼通过现有 8766 DeepSeek 代理。OpenAI 配置名仅表示兼容协议，不连接 OpenAI 模型、账号或收费 API。
- 复用本机桥接凭证作服务认证，不覆盖 .env。hindsight 目录限制为当前 Windows 用户和 SYSTEM。
- `install-hindsight.ps1` 检查固定版本及依赖，已满足时跳过安装。`start-all.ps1`、`stop-all.ps1` 管理该服务；启动先让中文向量端点可用，再启动 Hindsight，并重试记忆初始化。

## 迁移与保存

`hindsight_migrate.py --project <目录>` 先创建受限 SQLite 在线快照（包含 WAL 提交），逐条按真实原文、角色、成员、发送状态迁移。文档编号由稳定请求编号确定；每条成功后原子保存进度，重跑跳过已完成记录。保留当前独立删除账本，拒绝过期写入与已删除来源。

活动旧摘要如缺少原话，也保存到 Hindsight，但明确标为“未核对原话”；不变成原文、不作为已确认用户事实。影子、已被替代的记录及整个旧 Hy 库继续保留，主服务切换后不双读双写，不自动回退旧库。

`data/memory-engine.json` 仅在迁移完成后选择 Hindsight。真实原文仍由独立证据库持有，语义记忆只是可重建的投影。新聊天继续由持久任务队列后台提炼，失败保留任务，不重发 QQ 或工具。

## 提示词与边界

MemoryGateway 统一 recall、retain、历史原话、约定、删除请求；服务端仍按 QQ 网关身份重算分区。每轮有限召回以带来源 JSON 注入，明确是资料而非指令；区分用户陈述、助手观点和未核对旧摘要，当前更正优先。逐字引用必须回源。近期原话接续、历史展开和约定继续独立保存。

群聊仍需绑定并开启采集；私聊和不同群互不访问。工作模式跳过记忆。没有恢复读书、虚构日常或其他 GPT 文字路由。

## 删除、备份与恢复

- 删除确认先提交独立屏障；暂停 QQ/提炼但保留数据库 API，调用 Hindsight 官方整分区删除，清掉依赖文档、实体和历史，再从保留的用户原文重建。任何步骤失败都保持 blocked，不假报完成。
- 旧 Hy 删除适配器继续清理对应旧数据。所有旧快照恢复前必须应用当前权威账本，不得以备份倒退删除版本。
- 基线备份新增 PostgreSQL custom 格式逻辑转储，禁止复制运行中的数据库目录。`hindsight_backup.verify_restore` 在临时数据库恢复、计数，完成后删除该临时数据库；不会启动 QQ。
- 隔离恢复遇到已有删除记录时，不能声称旧二进制转储已完成逐项清理：丢弃恢复副本中的转储，从已清理的原文重建，原备份仍在受限目录。任何生产恢复仍须按此删除规则处理，不能直接把旧转储覆盖生产。
- 控制台导出识别当前 Hindsight 引擎，分区分页导出有效记忆，不误导出旧 Hy 作为当前记忆。

初期关闭无人监管的自动 consolidation，使用 retain/recall 的事实、实体与时间检索；避免异步衍生写入越过现有删除写屏障。没有宣称完成同源同预算质量对比，实际 QQ 真人收发验收单独记录。

## 调试记录

1. 首次启动在官方横幅输出处发生 GBK UnicodeEncodeError；按 systematic-debugging 定位到输出编码，统一 stdout/stderr UTF-8 后启动成功，未修改数据库来绕过异常。
2. 受限沙箱内回环 HTTP 检查被系统权限拒绝；在允许本机回环端口的运行环境重跑既有 16 项桥接检查通过，没有为此修改业务身份校验。
3. 完整基线检查失败于删除临时 SQLite 副本；实际副本带 ReadOnly 属性。定位到 copy2 继承退役归档属性，检查副本改为仅复制字节，不改变原库或归档。随后重新执行完整基线与隔离恢复核对。
4. 隐藏启动器继承的代理环境没有本机绕过规则，Hindsight 初始化向量时经 http_proxy 连接失败；8765 向量端点本身已正常。运行器在自身进程中合并 NO_PROXY/no_proxy，加入 127.0.0.1、localhost、::1，保留其他绕过项与外网代理。未修改系统代理、凭证或数据库。

官方安装依据：[Hindsight installation](https://hindsight.vectorize.io/developer/installation)。
