# V3.2.2 活跃群正常对话

问题：用户要求尽可能接话，上一轮仅开启群友模式并设为活跃。实际群事件已到达，但旧活跃档依然走旁听判断，记录出现“本轮选择倾听”和“普通插话冷却”，用户没有收到回复。

修复：已绑定、开启的活跃群收到普通人类消息（包括没有配文的图片、文件或引用媒体）时，直接进入与@消息共用的正常QQ Agent对话链路，不再经过3条消息门槛、NO_REPLY判断、15秒判断冷却或45秒/每小时24条旁听限额。不把普通消息伪标为真实@。SDK既有并发合并、会话、身份、原文记录、工具guard和实际发送回执处理继续工作，连续消息可能合并回答。

群关闭或暂停仍有效；机器人回声、仅凭证占位、未呼唤机器人的斜杠命令及指向其他成员的@不会触发普通活跃回复。真实@和名字呼唤保留原有处理，正常/安静档仍由旁听模型选择是否插话。仅对既有绑定的活跃群生效，不自动授权未知群。

元数据normalTurnsRouted与“活跃模式进入正常对话”只证明路由，不代表平台已接受。平台结果仍查独立原文库的assistant accepted/rejected/unknown，不能以旧sent累计数或服务健康宣称实际回复。不得重放历史群消息或重新执行旧工具来验收。

回归先在旧版复现15项中5项失败、10项通过；修复后群路由、身份、原文回执与私聊主动消息共73项不同检查通过；附件边界补齐后19项群路由检查再次通过。部署后验证实际安装模块并独立观察新群事件与平台接受状态。

产品3.2.2、插件0.17.4；无数据库schema修改，不恢复读书/虚构内容，不改变课表、私聊主动频率、凭证或既有群绑定。


实际验收：新非@文字消息已有7条关联助手回复获得QQ消息ID（观察于0.17.3文字修复阶段）。最终0.17.4补齐无文字附件后，19项实际安装检查通过；新附件真人验收仍待触发。用户随后明确保留一个群“正常”选择性接话，另一个群保持“活跃”；不要自动把正常改回活跃。
