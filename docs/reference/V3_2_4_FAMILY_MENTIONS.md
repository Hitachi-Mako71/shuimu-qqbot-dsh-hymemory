# V3.2.4 人格、家庭身份与群成员@

产品3.2.4、插件0.19.1。用户要求撤销旧动物昵称，角色保持人类少女外貌、温柔端庄的公主气质。已从personality.md、私聊/群提示词、触发词和当前人设文档移除旧昵称及相关角色规则。

旧的“鱼”身体描写及“没有主人”助手回复不再自动注入近期转录、长期召回或旁听上下文。persona-policy.json记录一次角色修订和原文水位，新的原生会话路由不会恢复旧角色压缩摘要；其他真实原话可正常按身份接续。原始聊天证据及历史档案保留，不把清理角色误作物理删除整份记忆或课表。

家庭关系来自本机用户确认，名单保存在data/companion/family.json，名字和平台账号不写入公共仓库。爸爸复用已验证的现有主人网关ID，名字由本机确认。妈妈的名称先确认，账号不可仅按同名昵称或数字QQ号猜测。每轮提供当前发言者是否为已验证父母的事实，常见主人/父母身份问题有确定性答复，不再沿用旧否认。

妈妈账号确认有两种方式：爸爸在群里输入“设为妈妈”并使用QQ真正@妈妈一个账号；或由爸爸私聊发送“绑定妈妈”，取得10分钟一次性认亲码，再由妈妈自己的账号私聊发送返回的“认亲：认亲码”。群转发码不能直接绑定，未验证成员不能发起绑定。此功能不合并双方私聊、不自动改变管理权限或群控制人。

工具qqbot_group_members只读取当前已授权群的近期真实网关成员及结构化@资料。list返回近期观察的成员编号，resolve根据当前发言者、已验证爸爸/妈妈、实际昵称或成员编号生成QQ成员标记。重名返回候选、缺失要求澄清；不猜OpenID，不以数字QQ号替代，不@全体，不跨群。

工具只解析标记，不另发消息；模型须把返回的markup原样嵌入最终回复。出站会校验成员确在当前群资料内。当前使用新版qqbot-at-user标记，实际SDK构造msg_type=2的Markdown，代码例子与原始标签有所区分。合成SDK构造和DeepSeek工具调用已验证；0.19.1安装后，用户再次发出请求并确认QQ客户端出现真正可点击的@，本地也记录了带成员标记的Markdown已被平台接受。这不代表设备已读。

参考：本机@tencent-connect/qqbot-nodejs 1.0.5的sendMarkdown显式构造Markdown；新版标记实现可参照[NoneBot QQ适配器源码](https://github.com/nonebot/adapter-qq/blob/master/nonebot/adapters/qq/message.py)。

验证覆盖147项Node检查，19项Python删除/课表生命周期检查通过。真实DeepSeek合成探针通过：在旧错误助手发言后按当前人格认出父母，并实际调用成员工具生成正确标记；探针没有向QQ发送消息。

部署保留群档位、自定义限额、私聊频率、登录、凭证、课表、原文和Hindsight主引擎。仅更新当前人格、角色修订和家庭配置，清理运行缓存中的废弃角色材料。

## 真实请求遗漏的补丁

0.19.0真实QQ截图证明父母身份有效，但模型虽看到成员工具仍只回问候、未执行@。0.19.1把明确的“@我打个招呼”“艾特爸爸问声好”“@本群昵称打个招呼”接入确定性成员解析，真实markup由现有SDK Markdown链路发送；不再依赖模型是否选工具。正常群也把这种明确请求交给正常处理，普通闲聊仍选择性接话。其他@任务继续使用成员工具，提示词明确其属于平台操作，并禁止无依据的等待或漏听说法。合成测试不代表QQ客户端渲染验收。

最终验收：147项源码Node检查、107项实际安装文件Node检查通过；本次人格/身份版本已有19项Python删除与课表生命周期检查通过。真实QQ确认能认出爸爸和妈妈的名字，明确@问候已由用户确认显示真实可点击@；妈妈网关账号尚待一次确认，不按同名昵称猜测。QQ、记忆与DeepSeek代理健康，36个安装文件一致，7个官方补丁文件保持原样。
