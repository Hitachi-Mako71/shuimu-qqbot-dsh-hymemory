# V3.5 聊天策略部署与维护

2026-10-27 部署版本为产品3.5.0 / 插件0.22.6；控制台2.9.0继续保留。策略按当前版本维护；示例中的开关不覆盖已有用户偏好。

## 日常行为

私聊短时间连发会保留顺序和附件、合成一次输入；原文仍逐条按原身份归档。先承接具体内容，不固定每轮反问，忙碌/告别自然收尾。“我先忙了，晚点聊”沿用2小时忙碌静默，恢复聊天可以解除；跨会话主动消息仍保留原授权和夜间免打扰。

群内真正@、叫名字、引用她的消息并追问进入完整对话；明确问其他成员时让对方先答。同一成员、同一话题短期承接可继续，但不会让整群永久变成单人对话。不同成员请求串行处理，各自身份不合并。明确呼叫不受普通旁听的冷却限制，仍受用户选择的“包含直接回复”与物理接口限流约束。

普通接话继续按原群档位与自适应占比评估。候选携带目标、来源、话题、版本、有效期；有人已答、更正前提、关闭或暂停、过期时放弃。无人承接的同一主动话题不连续推送，出现独立有效问题可重新评估。普通群不开主持功能，不因沉默点名成员、不私信潜水成员。

## 配置与控制

新增参数文件为生产目录 `data/companion/turn-settings.json`，格式见插件 `turn-settings.example.json`。`defaults` 为全局，`conversations` 使用现有稳定身份namespace覆盖；用户私聊与群分别配置。该文件只存参数及已知机器人ID，无私人事实。`enabled` 只控制新消息合并；群主动参与仍由既有群友模式控制。

| 参数 | 当前起点 | 含义 |
|---|---:|---|
| privateQuietMs / privateMaxWaitMs | 1200 / 3500 | 私聊合并静默窗口 / 第一批最长等待 |
| directQuietMs / directMaxWaitMs | 700 / 2000 | 群同作者短连发合并窗口 / 上限 |
| candidateTtlMs | 12000 | 普通群候选从目标消息起的最长有效期，含生成和发送排队 |
| quietGapMs | 2500 | 期间出现其他消息时避开连续交流的最短空隙 |
| followupTtlMs / implicitMaxTurns | 120000 / 2 | 无显式@的同话题承接时限与链长；真引用追问重新判断 |
| maxUnanswered | 1 | 无人承接的同一主动话题连续发言上限 |
| maxBatchMessages / maxBatchChars | 16 / 12000 | 单批条数与字符上限 |
| knownBotIds | 空列表 | 需明确配置的其他机器人实际ID；自身由网关识别 |

字段必须为有效整数、窗口不超过最大等待。合并只是形成输入的等待，不承诺模型在3.5秒完成回答。较慢生成超过普通候选TTL会放弃，真正@的复杂问题不套用该TTL。参数从磁盘读取，下轮生效；调整后由本机维护者核对，不能让群成员用闲聊直接修改文件。

已有QQ命令和控制台保持：群友模式状态、群友频率、群聊节奏；每分钟条数、每小时条数、间隔与是否包含直接回复沿用原配置。“关闭群友模式”只停止普通主动接话，明确呼叫可答；“暂停主动消息”暂停私聊跨会话主动问候，不取消正常问答。/stop、/new及删除命令保持原权限和原生处理，不由模型解释或伪装执行。

## 接入、原文与发送边界

修改真实SDK中间件：归档/去重后，命令和原生并发前合并。队列有界并在会话内串行，控制指令绕过等待；取消使等待批次及尚未执行的批次失效。生成中同作者明确更正会阻止旧版发送，无关成员发言不取消有效直接回答。

普通候选在最终发送排队时再次复核；同一会话原子预留单个槽位。真实平台返回message ID才提交成功与逻辑冷却；未知结果保守记录，不自动重发。物理消息限额按实际发送尝试预留，未知请求也占尝试额度，避免超限。删除、权限、来源守卫在真实发送前继续执行。

合并后的原文来源、近期双方原文和记忆回源ID都进入既有删除关联。临时路由提示只放在已有身份room文件及有界短期内存；保留原30分钟room/删除生命周期，不新建长期私人事实库。控制或关闭再开启的epoch不同，旧候选不能复活。本次未重置任何生产会话，未重跑全库导入或提炼，也未改变原记忆权威。
