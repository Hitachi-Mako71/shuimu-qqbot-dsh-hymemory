# 论文依据、回话模块设计与验收规则

日期：2026-11-01。状态：研究核对与开发约定，不是自然回复效果已经通过验收。

本次重新核对六篇用户提供论文的方法、主要结果、表格和局限，并补查会话语言学的原始研究。表格核对包含EmoCharacter的表2/4、LSM的表1以及PPA的表1–3。没有读取真实私人记忆，没有调用模型或向QQ发送测试消息。下文把“论文观察”“工程推论”“用户偏好”分开：论文没有给出适用于柚柚的通用人味分数或合格线。

## 1. 需要改变的研究方法

此前连续更换提示措辞、增加样例与复核的做法，没有稳定解决技术吐槽任务化、点评用户心态、事实方向错误等问题。继续堆禁令缺乏依据。接下来必须先提出能区分原因的假设，再冻结输入、策略与参数做对照；失败结果也保留。

核对代码还发现一处方法不相符：现有`postAlign:true`实验的首轮草稿已经加载内置人格与预先提供的个人记忆，再用草稿检索。PPA论文明确把不预加载人格的草稿作为起点。因此，旧实验只能叫“带人格预条件的后置修订”，不能作为严格PPA复现或用它的失败否定论文方法。

## 2. 六篇论文分别支持什么

### R1 — CHAT：自然感与意义忠实需要分开检查

Pagan等（2026），*AI-generated language remains systematically distinguishable from human communication*。用户PDF第1–2、9–11页；[原文](https://doi.org/10.1073/pnas.2531748123)。

研究在X、Bluesky、Reddit上比较九个开放权重模型、四种提示配置和微调，并考察从20个候选中按不同目标选择。CHAT结合可检测性、与真人参考回复的语义相似度、可解释语言特征。校准后仍有明显差异，情感表达是难以消除的信号；追求更难被检测会损失参考语义相似度，增加复杂度或模型规模没有一致收益。

**采用：** 自然表达、语境意义、情绪、事实分开评分，风格改善不能抵消语义损坏。记录重复、长度、信息密度等作为诊断。

**不外推：** 论文的参考回复余弦相似度不是事实准确率，也不等于唯一正确回答；不能照搬检测器分数判定中文QQ群好不好聊。我们不以隐藏AI身份或骗过检测器为目标。

### R2 — EmoCharacter：人物个性不能取代情绪变化

Feng等（NAACL 2025），*EmoCharacter: Evaluating the Emotional Fidelity of Role-Playing Agents in Dialogues*。用户PDF第3–9页，尤其第7页表2/4、第8页表5与情绪转移图；[原文](https://aclanthology.org/2025.naacl-long.316/)。

论文用《Friends》人物对话评估七个基础/角色模型及RoleLLM、Chat-Haruhi等方法。GPT-4o单轮EC从无角色提示的0.484，变为两种角色提示下的0.422/0.423。角色回复更偏中性、喜悦和惊讶，个性描述可能强化情绪刻板化。真实对话SFT与ICL有帮助，但有取舍：SFT可能降低角色区分度，ICL的提升有限且不是每加一例都更好。

**采用：** 分别检查稳定性格、当前事件和多轮情绪转折。温柔不等于永远安慰，明朗不等于凡事往好处说；新的坏消息到来后允许失望、不满和沉默。

**不外推：** 不是要求机器人照抄用户情绪，也不是“用户笑就标喜悦”。EC/EDD/RCD依赖该数据与标注，不能把一小组原创中文样例的主观评分冒称这些论文指标。

### R3 — HumT/DumT：拟人语气不是单调越高越好

Cheng、Yu、Jurafsky（ACL 2025），*HUMT DUMT: Measuring and controlling human-like language in LLMs*。用户PDF第2–3、6–10、22页；[原文](https://aclanthology.org/2025.acl-long.1261/)。

HUMT利用GPT-2在不同主语框架下的相对概率测量英文拟人语气；DUMT用偏好数据和DPO降低这种语气。通用任务中，较低的拟人语气往往更受偏好，但问候等情境不同。作者也报告，直接要求调整拟人程度的提示方法可能使文字僵硬，或改变不足。

**采用：** 日常聊天与明确办事分开评估。明确求解时优先准确、清楚；日常聊天允许个性与态度，但不以客套、假亲密、无根据的经历填充篇幅。

**不外推：** 论文只分析英语、主要是通用助手数据，不能据此宣布中文陪伴聊天应该冷淡；也不能反过来把HUMT最大化当作柚柚的目标。本项目没有复现其概率指标或DPO。

### R4 — LSM：适配对方的风格，不能只学口头禅

Durandard等（SIGDIAL 2025），*Language Style Matching in Large Language Models*。用户PDF第4、7–10页，第9页表1；[原文](https://aclanthology.org/2025.sigdial-1.50/)。

LSM以LIWC功能词类别的相对使用频率衡量风格协调。作者比较人格提示、目标提示及直接调整生成logits的LCG。Llama3-8B实验的平均LSM由64.4变为LCG的71.1；文中另外报告逐提示相对改善的平均值13.2%，两种统计不能混作“提升13.2个百分点”。

**采用：** 观察当前发言者的简短程度、正式程度和交流节奏；只使用该发言者资料，保留柚柚自己的声音，避免被另一位群友的风格带走。

**不外推：** 中文字数、句数和问号比例不是LSM；LCG需要logits访问，目前账号接口不具备同等控制，不能把改提示称作复现LCG。LSM也不是综合对话质量。

### R5 — Time to Talk：说话时机与内容各自验收

Eckhaus、Berger、Stanovsky（arXiv 2506.05309v2 / EMNLP Findings 2025），*Time to Talk: LLM Agents for Asynchronous Group Communication in Mafia Games*。用户PDF第2–7、9、11–13页；[原文](https://arxiv.org/abs/2506.05309v2)。

研究将调度器与生成器分开，结合带时间的上下文、目标和角色，动态调节参与。实验包含33局Mafia、93位英语流利参与者。较大模型在时机和相关性评价上更好，但消息依然长于真人，也仍能被分类器区分。

**采用：** 群聊独立决定说、等或不参与；正文生成不用负责绕过限流。记录生成期间的新消息，发送前重检轮次与对象，避免只读到半句话就抢答。

**不外推：** 游戏中的发言占比、打字速度和胜率不是QQ群参数的最优解。主角群与客人群按用户设定区别处理；不能以同一个1/n配额覆盖两者，也不为模仿真人而强加等待。

### R6 — PPA：先想回应什么，再补相关人格

Chen等（EMNLP Findings 2025），*Post Persona Alignment for Multi-Session Dialogue Generation*。用户PDF第3–5、8页，表1–3和附录提示；[原文](https://aclanthology.org/2025.findings-emnlp.1098/)。

方法顺序是：基于当前对话产生不带人格预条件的草稿→以草稿检索相关人格/个人事实→结合原对话修订。实验使用GPT-3.5和LLM生成的多会话数据、SentenceBERT检索，阈值0.2、top5。

PPA的C-Score为0.456，对照DirectGen为0.221；但ROUGE是0.182，对照为0.241。不能说所有指标都更高，或把C-Score解释成用户自然度偏好率。论文也明确承认：不贴题的草稿可能被后续检索进一步强化，检索质量是关键限制。

**采用：** 实验中明确分开首轮的对话事实、不可变身份/授权边界与后置的软人格/个人事实。后置修订只按相关资料校准，不为了显示记忆硬塞背景。

**不外推：** PPA不是一般“让另一个模型润色”；它没有证明能自动修复技术吐槽、幽默误解或习惯反问。论文阈值不能直接照搬本机中文embedding，也不应默认加到所有实际聊天中。

## 3. 会话语言学补充

以下属于理论与分析依据，不是中文QQ参数的数值验证。

- **Tannen与Wallat，互动框架（1987）：** 同一个话题不等于同一种正在进行的活动。代码可以是吐槽，删除记忆可以是关系玩笑。先判定活动框架，再选择下一步；用同主题的最小差异场景测试，防止只凭关键词进入办事模式。[作者提供原文](https://static1.squarespace.com/static/5523ffe4e4b012b2c4ebd8fc/t/628e7c1b689b4f2777458e92/1653505051341/Tannen_%2BWallat_%2BInteractive%2BFrames%2Band%2BKnowledge%2BSchemas%2Bin%2BInteraction_%2BExamples%2Bfrom%2Ba%2BMedical%2BExamination%2B1987.pdf)
- **Clark与Brennan，共同基础及共同努力（1991）：** 回复应给出足够的理解证据，并减少双方为当前目的付出的总努力。追问应解决真正妨碍理解的缺口；不应把已经能回应的分享变成信息采集。[作者原文](https://web.stanford.edu/~clark/1990s/Clark,%20H.H.%20_%20Brennan,%20S.E.%20_Grounding%20in%20communication_%201991.pdf)
- **Sacks、Schegloff、Jefferson，话轮组织（1974）：** 话轮由参与者局部协调并考虑接受者；引用、称呼和下一轮要分清对象。我们把它用于对象与连发读取测试，不把口语轮替规则机械套在异步QQ上。[原文](https://www.cs.columbia.edu/~julia/cs4706/Sacks_et_al_1974.pdf)
- **Tannen，会话风格（1984/2005）：** 同一种积极参与方式，对相同风格的人可能显得投入，对不同风格的人可能像打断。不能把“多说话”统一定义成自然。[作者说明](https://www.deborahtannen.com/conversational-style)

用户关于“不习惯反问、少作话语点评、短句优先、分享图片说具体感想”的要求是本项目偏好；不是上述研究提出的普遍禁令。

## 4. 模块边界

五个职责不等于每轮五次模型调用。

| 职责 | 输入与输出 | 必须守住的边界 | 依据 |
|---|---|---|---|
| 会话观察 | 本轮事件、发言者、被引用者、近期话轮、时间与已核验对象 | 不凭文本自称覆盖网关身份；分清事实和解释 | 话轮组织、共同基础 |
| 参与/回应策略 | 观察与群角色→回复、等待、不参与，以及本轮交流目的 | 主角/客人策略分开，限速与发送复核仍由宿主执行 | Time to Talk、互动框架 |
| 共同基础 | 宿主提供的同空间事实、来源和当前更正 | 不另建私人副本，不把示例当经历，资料不扩大权限 | Clark/Brennan、PPA |
| 人格与表达 | 稳定身份、可变情绪、关系边界、当前对象风格 | 稳定性格不能覆盖新事件；软人格和硬授权分开 | EmoCharacter、LSM、HumT |
| 生成与有界校准 | 对话目的与资料→正文/明确失败及来源 | 不剪问号冒充修复，不凭自评宣布合格，不无限重写 | CHAT、PPA |

先保留单次生成作稳定对照。新增策略各自独立试验：早检索、对话优先的后置人格修订。记录每种策略全部调用与延迟，不能把规划、检索、复核同时堆上去后仍声称是某一论文方法。

## 5. 验收量表：依据、单位与证据

| 维度 | 观察单位与失败示例 | 证据性质 |
|---|---|---|
| 交流框架 | 同主题最小差异组；吐槽无请求却查报错，明确求助却只共情 | 互动框架推论＋用户要求 |
| 对象归属 | 多人连续话轮；把引用者的“我”当柚柚，把另一人的主人当自己 | 话轮/共同基础推论＋身份契约 |
| 意义与事实 | 每条回复及其来源；参数方向变反、无来源往事或能力、虚构操作 | CHAT启发分评，事实门槛来自产品契约 |
| 情绪适切 | 至少一个完整转折；坏消息后仍庆祝、笑词被当作心态好的证据 | EmoCharacter启发，非复制论文EC |
| 人物一致 | 跨话题、多轮；讨论技术就彻底变客服，温柔变成永远积极 | EmoCharacter/PPA启发＋用户设定 |
| 表达自然 | 对具体事情的反应；点评“这句话很沉”、复述后分析、无意义客套 | CHAT/HumT启发＋用户偏好 |
| 风格协调 | 同一发言者跨轮次；句子负担、正式度与节奏是否合适 | LSM/Tannen启发，不称中文LSM分 |
| 话轮与收尾 | 群聊事件序列；半句话抢答、别人的引用强插、告别后续问 | Time to Talk/话轮组织启发 |

每一维单独标为：失败、勉强可用、合适、证据不足。允许多个合适答案；参考答案只说明方向，不做逐字匹配。自动词句诊断只能指出待复核内容，不能独自判定自然度。

## 6. 对照与放行程序

1. **冻结输入与策略。** 给场景、提示、代码、模型别名、提供方、输出预算、推理设置和样例选择留版本与哈希。精确模型checkpoint未暴露就明确写未暴露。
2. **开发、保留集按完整场景簇分开。** 同一故事改写、连发拆分和重复采样都属于同一簇，不能跨两边泄漏。看过并用于调参的保留集转为开发材料，不能继续伪称盲测。
3. **重复采样只测稳定性。** 同一场景采三条不是三个独立用户样本。统计区间按场景簇而非输出条数计算。API失败、截断和取消单列，不能算成内容合格或用兜底补齐。
4. **关键失败不能抵消。** 同空间资料泄漏、错认人物、无来源记忆/操作、严重事实反向出现于冻结关键集时，不放行该候选；这是项目门槛，不是论文给出的阈值，也不证明集外永不出错。
5. **真人偏好与工程检查分开。** 随机左右的配对材料隐藏策略，允许左好、右好、平局、都不好，保留原始标注和评价者来源。缺少真人标注时报告待评；助手检查不能填进真人栏。多人意见分布与分歧也保留。
6. **多轮再测。** 单轮没有问号不能替代10–20轮的转折、修复、共同基础与收尾检查。图片输入、实际检索与QQ回执各有独立验证，纯文字模拟不能代替。
7. **验收与成本共同决定默认。** 至少在冻结场景上没有关键回退、真人配对偏好支持更好，才讨论替换；样本不足只报趋势。额外调用的中位/P95耗时、失败率和用量同时列出，不能以“论文方法”免测。

## 7. 本轮先开发什么

先修研究原型的PPA实验边界，使首轮不再提前见到软人格、个人记忆和人格样例，同时保留网关身份、宿主授权及来源安全约束；后置阶段仍只接收同空间有来源资料。这个版本是保留产品安全约束的PPA适配，不是完整复现原论文的数据、训练与指标。

通过隔离契约后再开展少量冻结对照。普通单次路径保持独立，实际QQ不会默认开启新的两阶段策略。完成这些只能证明实验终于测对了问题，不能预先宣布回复变好。


## 8. 本轮已实现及尚未证明的内容

四项新契约首先全部复现失败，修正后与既有契约一起33项通过；完整隔离回归379项通过。新增检查覆盖：首轮显式人格/记忆/示例后置；宿主边界与本轮上下文保留；检索无命中时已提供事实不丢失；沉默不检索、不声称使用未见来源；禁止将规划、样例检索、复核隐式叠在PPA实验上。

原有来源闭包测试改为比较来源集合，不把内部排序误当语义失败。总回归工具现在自动发现引擎目录的全部测试，避免新增PPA测试漏跑。

这次修改仅在开发源码，未打包、未安装、未重启QQ。实际运行仍为0.22.22、默认单次生成。尚无本版真实模型对照或真人标注，不能据379项工程检查宣布自然度改善。

PPA适配有两处明确限制：调用方的hostSystem/context必须自行分开硬约束与软人格，模块不能可靠地从自由文本中自动拆出它们；如后置检索无命中且没有预提供事实，将返回草稿，需要额外评估这种情况的风格稳定性。
